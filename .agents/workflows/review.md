Use `code-review-and-quality`. Load `security-and-hardening` and `performance-optimization` when relevant.

Review the requested files, commit, branch, staged diff, or current uncommitted changes by default. Read the specification, applicable rules, tests, diff, and necessary surrounding code.

This workflow is read-only. Do not edit, stage, commit, push, merge, or deploy.

Return findings first in severity order with file and line references, then verification status, residual risks, and a verdict. Do not invent findings.
