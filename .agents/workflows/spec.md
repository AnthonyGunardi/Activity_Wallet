Use `spec-driven-development`.

Take input from the command argument, a referenced idea document, or the current conversation. Use `interview-me` first when unresolved decisions affect scope, architecture, or risk.

Inspect the repository before documenting commands, versions, structure, and conventions. Use `source-driven-development` for version-sensitive decisions.

Create or revise `SPEC.md` according to the skill contract. Present a concise summary and wait for explicit approval. Revise and repeat the gate when feedback arrives.

Do not plan or implement before approval. Return the artifact path, approval status, and unresolved questions.
